6月15日の課金分離の構造の整理

5月13日に Anthropic は購読者に通知の便りを発送しました。 6月15日の発火の後、 自動の使用は購読の利用枠から別の月次の枠に分離されます。 対象は4つの経路。

  • claude -p の対話なしの派遣
  • 公式の自動の道具の組の経路
  • GitHub の自動の実行の経路
  • 第三者の作業者の道具の経路

対話の経路は変化なし。 各 plan の月次の枠の金額は購読の料金と同じ目盛りで、 Pro が20ドル、 Max 5x が100ドル、 Max 20x が200ドル。 枠は次月への繰越なし。

中核の単一の合図は、 枠が公式の値段で消費される事実。 同じ作業の量で、 購読の換算と公式の値段の換算には、 軽い作業で約12倍、 重い作業で150倍以上の幅の値段の差があります (5月13日の独立な分析と、 5月22日の業界の累計)。 業界の典型として、 独立な開発者の1日4件の PR の対の評価の自動の経路で、 公式の値段で約25ドル/月の消費の見込み。 Pro の枠の20ドルでは3週目で枯渇の予測。 5名の開発者が10件/日の自動の作業で運用する場合、 月の合計の消費は340から1,125ドルの幅。

22日の準備の7つの手順

第1、 受領の通知の便りの到来の準備

Anthropic は6月8日頃に対象の購読者に受領の便りを発送する見込み。 受領は1回の手動の発火で、 以後は自動の更新。 月額の購読者の準備は2つ。 第1、 購読の口座の便りの配送の確認 (迷惑の箱への振り分けの点検)。 第2、 受領を忘れた場合の影響の認識 (20、 100、 200ドルの枠の取得の遅延、 6月15日の発火の後の自動の経路の停止の可能性)。

第2、 自動の経路の棚卸し

自分の運用の中で6月15日の影響を受ける経路を全件で書き出します。 観察の対象は4つ。 claude -p を呼ぶシェルの文書や定期実行の経路、 GitHub の自動の実行で Claude Code の発火を含む経路、 公式の自動の道具の組を経由する自前の道具の経路、 第三者の作業者の道具の経路。

棚卸しの素案は、 月次の整備の点検の表に組み込み。 月の頻度の作業の上位3件、 日の頻度の作業の上位3件、 1回限りの自動の作業の上位3件の合計9件を最低の整備の対象として列挙します。

第3、 現在の使用量の取得

3つの公式の経路と1つの自前の経路があります。 Anthropic の請求の頁の利用量の閲覧、 公式の使用量と費用の API 経路 (/v1/organizations/cost_report、 管理の鍵が必要で sk-ant-admin で始まる)、 Claude Code の分析の API の日次の集計の取得、 加えて自前の経路は Claude Code が対話ごとに書き出す jsonl の経路 (~/.claude/projects/*/session-*.jsonl) を集計する経路。

5月の残りの期間で、 自動の経路の各々の入力と出力の字句の数、 蓄えの作成と読み出しの字句の数の月次の合計を記録。 6月15日の発火の後の差分の比較の基準値の整備。

第4、 事前飛行の検査の手順

起票61704 の€84.68の損失の事例で、 同じ起票の別の投稿者が articulate した防衛の手順。 自動の派遣の定期実行や作業者の群の起動の前に、 1件の手動の claude -p の派遣を発火し、 直後に Anthropic の請求の頁で実際の振り分けを観察し、 期待と実態の合致を確認する経路。

5月の残りの期間の整備の素案。 6月8日頃 (受領の便りの前後)、 6月15日の発火の翌日、 6月22日 (発火の1週間後) の3回の事前飛行の検査の手順を月次の作業に組み込み。 各々の結果は、 請求の頁の画面の写し、 自前の jsonl の集計の差分の記録で残す経路。

第5、 上限の自動の停止の仕組みの整備

起票61704 の損失の根本の原因は、 自動の派遣の経路が請求の上限を超過した時に停止しなかった事実。 月額の購読者の整備の素案は3つ。 日次の集計の閾値の警告の定期実行の整備 (枠の80%の時に便りや通知の発火)、 90%の時の自動の派遣の経路の停止の機構の整備、 99%の時の強制の停止の機構 (例えば仮想の鍵の経路で予算の鍵の自動の無効化、 観察の道具の経路で予算の警告の発火)。

自前の道具の素案として、 簡単な経路は定期実行で日次の curl での費用の API の取得と、 閾値を超えた時の通知の発火の組み合わせ。 詳しい設定例は6月号の続きの章の hook の節で articulate。

第6、 公式の鍵への切替の判定

自前の自動の経路の合計の月次の消費が、 自分の plan の枠 (20、 100、 200ドル) を超える見込みの場合、 別途の公式の鍵の経路への切替の判定が入ります。

判定の入力の3つ。 既存の自動の経路の月次の合計の消費の見込み (第3の手順の取得の結果)、 公式の鍵の経路の月次の追加の費用 (公式の値段で換算)、 OAuth の経路の禁止の事実 (2026年2月の公式の文書の更新で、 購読の OAuth の鍵を自動の道具の組で使う経路は禁止、 2026年1月に Anthropic は利用規約の違反として実機の措置を実行)。

切替の合図。 月次の合計の自動の消費が枠の200%を超える見込みの場合、 公式の鍵の経路の方が経済の側で合理。 100%から200%の幅の場合、 自動の経路の整理 (頻度の低下、 模型の切替) の素案。 100%未満の場合、 現状の枠の経路で持続。

第7、 6月15日の発火の前後の差分の取得

5月22日から6月22日の31日の固定の定期実行の負荷を維持し、 6月15日の発火の前後の差分を観察します。 観察の対象は4つ。 同じ作業の量の月次の合計の入力と出力の字句の差分、 蓄えの命中の率の差分、 同じ作業の量の月次の合計の費用の差分 (購読の換算から公式の値段の換算への変化の幅)、 自動の経路の停止の発生の有無 (枠の枯渇の経路)。

差分の整理の素案は、 6月22日 (発火の1週間後) と6月30日 (発火の2週間後) の2回の整理の段で記録。 整備の結果は月額の購読者の自己診断の経路の入力。

警告の3つの予兆

予兆1、 OAuth の鍵の経路を自動の道具の組で使う

2026年2月の公式の文書の更新で、 購読の OAuth の鍵を自動の道具の組の経路で使う事は禁止。 2026年1月に Anthropic は利用規約の違反として、 OAuth の鍵を抽出して別の作業者の経路で使う第三者の道具に対して実機の措置を実行しました。 自前の作業者の群の整備で、 購読の OAuth の鍵を抽出して連続の派遣を発火する経路は、 利用規約の違反で口座の停止の経路。 整備の素案は、 自動の経路は全件で公式の claude -p の道具の経路で発火するか、 別途の公式の鍵の経路に切替で運用する経路。

予兆2、 模型に請求の経路を聞く

起票61704 の€84.68の損失の根本の原因。 模型は Anthropic の請求の仕組みを構造的に読まない、 にもかかわらず「これは課金されますか」 の問いに対して確信の説明を生成します。 整備の素案は、 請求の経路の判定の入力は全件で公式の文書と請求の頁の実機の取得から取得し、 模型からの説明は信頼の源としない規律。

予兆3、 受領を忘れる

6月8日頃の受領の便りを見落とすか迷惑の箱に振り分けされた場合、 枠の取得の遅延の経路。 5月の残りの期間の整備の素案は、 Anthropic の便りの白の名簿への登録 (@anthropic.com の経路の優先の整備)、 加えて、 6月8日から6月14日の期間に毎日受領の便りの到来を点検する手順の月次の作業の追加。
