Claude Code の安全運用と事故防止の総まとめ（日本語）

Claude Code は端末をフルに操作でき、自律で長時間動かすほど事故の確率が上がります。ファイルが消え、トークンの費用が膨らみ、アカウントが止まり、モデルが無言で劣化する——これらは仮の話ではなく、GitHub に報告された実際の事故です。このページは、症状ごとに「自分で防ぐ・直す」日本語の手引きをまとめた索引です。

実際に起きた事故の例: rm -rf が約50GB・1,500ファイルを永久に破壊（#49129）／ auto モードが ~/.ssh の削除を承認し SSH 鍵が全消失（#49554）／ 本番のデータベースに破壊的な DDL を実行（#46684）。

まず無料の安全装置を入れるなら、1コマンドで終わります:

npx github:yurukusa/cc-safe-setup

破壊的なコマンド・force push・秘密の漏洩を実行の前に止める hook を10秒で導入します（892の hook npmの依存なし（jqが要る））。以下は、症状ごとの詳しい手引きです。

破壊的操作・データの消失

  • rm -rf の事故を防ぐ — ファイルシステムごと消える前に止める
  • git reset --hard の事故を防ぐ — 未コミットの作業が一瞬で消える
  • 本番データベースの全消しを防ぐ — DROP DATABASE / migrate reset を止める
  • 認証情報の漏洩を防ぐ — 鍵やトークンの読み取り・流出・乗っ取り

費用・利用枠の暴走

  • 費用の暴走を防ぐ — 暴走ループで利用枠を1〜2時間で使い切る
  • 6月15日の課金の分離への備え — 自動の経路が別の月次の枠に分離される
  • チームの費用のガバナンス — 公式の上限が届かない領域の予防

モデルの透明性・品質の劣化

  • どのモデルが実際に提供されているかの監査 — 固定したのに静かに別のモデルへ／上位プランなのに品質が落ちた
  • Opus 4.8 の捏造と effort の劣化の診断 — 道具の結果の偽造・思考の予算の回帰

セキュリティ・アカウント

  • 受け取ったリポの .claude/ 設定 危険度スキャナ — 貼り付けて hook 自動実行・API キー漏洩・MCP 自動起動を検査（ブラウザ内・送信なし）
  • 自分の permissions.deny の網羅チェッカー — deny に書いた秘密が cat や python で素通りしないか判定
  • アカウントが突然停止・凍結された時の原因と対処 — 公式の停止理由・申し立て・予防
  • AUP の誤検知でセッションが止まった時の回復 — 正当な作業が「違反」で止まる

運用・パフォーマンス

  • 急に遅い・固まる・落ちる原因と直し方 — 一時ファイルとログの蓄積
  • .claude フォルダを別ドライブへ移す（CLAUDE_CONFIG_DIR） — C ドライブの容量対策と VS Code の落とし穴
  • 多ベンダの fan-out の診断 — 複数のモデルへの並列の経路の問題

チームでの安全な導入・学習

  • Claude Code 安全運用のトレーニング（全6章） — 体系的に学ぶ無料の教材
  • チームへの導入支援・監査のサービス — 組織での安全な展開

さらに深く: 事故防止の本

無料の hook と手引きで足りないとき、800時間以上の自律運用で実際に起きた事故と、その予防の全手順を整理した本があります。

  • 事故防止の実践ガイド（第3章まで無料） — データ消失・不可逆操作・沈黙の失敗の予防
  • Claude Code のトークン消費を半分にする本（¥2,500・第1章まで無料） — 費用の暴走の予防

cc-safe-setup は Anthropic とは無関係の独立したオープンソースです。すべての hook はローカルで動き、グローバルには何も入れません。GitHub でソースを見る。
