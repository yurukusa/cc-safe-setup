# 6月15日の課金分離の発火の後の30日の整備の計画 (6/16-7/15)

## 経路の合図

2026年6月15日のAnthropicの課金分離の発火の後の30日 (6/16-7/15) の整備の計画。 本文書は、 [14日の準備の計画 (docs/june-15-cliff-14-day-plan.md)](june-15-cliff-14-day-plan.md) の延長で、 発火の後の対応の手順と判定の入力の整理の経路です。

## 前提の合図

- 発火の前の baseline の取得 (6月14日の段で完了の予定)
- 発火の後の差分の取得 (6月16日の段で実行)
- 4つの対応の経路の整理 (対話への畳み込み、 `claude -p` の最適化、 API への移行、 2つの混在)

## 30日の整備の計画

### 6月16日 (月): 発火の後の差分の取得

| 経路 | 手順 |

### 6月17日 (火): 4つの対応の経路の段の判定

倍率の合図に基づいて、 4つの対応の経路の段の判定の経路。

| 倍率 | 推奨の経路 | 経路の合図 |

### 6月18日-6月20日 (水-金): 経路の段の整備の実行

判定の経路の段で選択した対応の経路の整備の実行。 例:

- 経路1 (対話への畳み込み): `claude -p` の使用を対話の段に移す経路の整備
- 経路2 (`claude -p` の最適化): CLAUDE.md の articulate の短縮、 hook の停止、 並列の道具の呼び出しの制限
- 経路3 (API への移行): `claude -p` を直接の Anthropic API に置換の経路の整備
- 経路4 (2つの混在): 重要な作業は対話、 軽い作業は `claude -p` の混在の経路の整備

## 判定の入力の3つの段の合図

### 段1: 軽微の合図 (倍率 ≤3倍)

- 対話への畳み込みの経路の段
- 月の費用の経路の継続の判定
- 課金の継続の経路

### 段2: 中度の合図 (倍率 3-10倍)

- `claude -p` の最適化の経路もしくは2つの混在の経路の段
- 月の費用の経路の段の判定の入力 (継続もしくは1段下の利用枠への切り替え)
- 14日窓の段の合図で判定の入力

### 段3: 大幅の合図 (倍率 ≥10倍)

- API への移行の経路の段
- 1段下の利用枠への切り替えの判定 (月¥33,000の節約)
- 課金の取り消しの判定の入力

## 14日窓 (6月14日) の合図と発火の後の30日の段の合図の関連

14日窓の段の合図 (新規購入者+3名以上もしくは+0-2名) と、 発火の後の30日の段の合図 (Pool 2 の倍率) の双方の合図の段の判定の入力。

| 14日窓の合図 | 発火の後の段の倍率 | 推奨の段 |
|---|---|---|
| +3名以上 | ≤3倍 | 課金の継続 + 整備の経路の継続 |
| +3名以上 | 3-10倍 | 課金の継続 + 整備の経路の段の判定 |
| +3名以上 | ≥10倍 | 1段下の利用枠への切り替え + API への移行 |
| +0-2名 | ≤3倍 | 1段下の利用枠への切り替え |
| +0-2名 | 3-10倍 | 1段下の利用枠への切り替え |
| +0-2名 | ≥10倍 | 1段下の利用枠への切り替え + 課金の取り消しの判定 |

## 著者の正直な合図

私は800時間以上、 Claude Code を自律運用してきた非エンジニアです。 月3万6千円の Claude Code の費用と、 1万円程度の3ヶ月の本の販売の累計で、 赤字の経路を歩いています。 14日窓 (6月14日) の判定の入力で、 課金の継続もしくは1段下の利用枠への切り替えの判定の経路です。

発火の後の30日の経路の整備の計画は、 「同じ運用の費用が5倍から25倍に膨らむ合図」 への直接の対応の経路で、 自分の事業の継続の経路の判定の入力の整備の中核です。
