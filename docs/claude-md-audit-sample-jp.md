# 見本：CLAUDE.md Audit（指示ファイルの監査）

これは実際の報告書だ。機微な行だけ伏せてあり、それ以外は手を入れていない。[¥3,980 の CLAUDE.md Audit](https://yurukusa.github.io/cc-safe-setup/claude-md-audit-jp.html) の納品物そのものを、見本として公開している。

対象は私自身の指示ファイル——グローバル・ホーム・プロジェクトの3層、608行、日本語で書かれていて、自律で動く Claude Code のセッションを動かしている。お客さんのファイルにかけるのと同じ検査をかけた。

下の件数と比率は全行を対象にしている。引用は機微でない行に限ったので、**例を添えずに数字だけで報告している項目がある**。

> この文書は英語版 [`claude-md-audit-sample.md`](claude-md-audit-sample.md) と同じ内容の日本語版。数字も測定も同じものを使っている。

## 0. 要点

**この設定には、今日この時点で従うことが不可能なルールが1つあり、それを誰も報告していない。**

「ポートとプロファイルの割り当てはメモリ `cdp-ports.md` を参照する」という指示がある。そのファイルは存在する——ただし*別のプロジェクトの*メモリの領域に。このルールが効くプロジェクトからは、**名前では辿り着けず、索引にも出ない**。今日の時点で従えない。いつ壊れたかまでは調べていない。

2件目の参照が同じ形で壊れていて、しかも**私自身の自動の走査はそれを見落とした**。第3a節を参照してほしい。**その見落とし自体が発見だ。**

副次的な数字：ここにある指示の83%は機械的に検査できない。24組のルールが層をまたいで重複している。

**この監査が見つけ*なかった*もの：意味のあるトークンの費用。** 第1節を参照。

### 重複が実際にいくらかかっているか

層をまたぐ24組の重複（第3b節）は、1ターンあたり794トークン、全体の5.4%にあたる。

| 前提 | 月200ターン | 月1,000ターン |
|---|---|---|
| キャッシュ外の入力 @ $15/Mtok | $2.38 | $11.91 |
| キャッシュ読み出し @ $1.50/Mtok | $0.24 | $1.19 |

`CLAUDE.md` はキャッシュされる前置きに乗る。だから請求に届くのは下の行のほうだ。

**この設定で重複したルールを全部消して、浮くのは月およそ $0.24〜$1.19。**

設定がもっと大きければ計算は比例するが、**その塊がキャッシュに乗っている限り形は変わらない**。重複を直す理由は、費用ではなく「どの層がそのルールを持っているのかが曖昧になる」ことのほうだ。請求が問題なら、金はセッションのログのほうにある。指示ファイルではない。

## 3. 重複と、腐った参照

### 3a. 腐った参照

抽出の規則：バッククォートで囲まれた文字列のうち、空白を含まず、スラッシュを含むか既知の拡張子（`.md .sh .json .yaml .yml .jsonl .py .txt`）で終わるもの。それぞれを10通りの妥当な基準パスに対して解決した。

**56件を検査。50件は解決する。6件は解決しない。** その6件の内訳：

| 解決しなかったもの | 判定 |
|---|---|
| `/sol`（2件）、`/post-article` | スラッシュコマンドであってパスではない。**欠陥ではない** |
| `~/ops/proof-log/YYYY-MM-DD.md` | ファイル名の雛形。**欠陥ではない** |
| `project/docs/` | ディレクトリの慣習を書いた節の中の一般名詞。**欠陥ではない** |
| `cdp-ports.md` | **本物の欠陥。** `~/.claude/projects/-home-namakusa/memory/` の下でしか解決しない。このルールが統べるプロジェクトは別のメモリの領域を使っていて、そこにこのファイルは無く、索引を引いても0件が返る |

これが研究に値する失敗なのは、**隠れ方**のほうだ。

- ファイルが無いわけではないので、「このパスは存在するか」という検査は**通ってしまう**
- 打ち間違いではないので、行を注意深く読んでも**現れない**
- 参照を**そのルールが動く領域に対して**解決し、なおかつ「当たったのは別の場所からだ」と気づいたときにだけ、表に出る

### 自分の走査が見落とした1件

`~/CLAUDE.md:69` に「ゲームは `GAME_QUALITY_FRAMEWORK` に従う」とある。このファイルは `~/projects/spell-cascade/GAME_QUALITY_FRAMEWORK.md` に在るが、**どの層もパスを書いていない**——`cdp-ports.md` とまったく同じ失敗だ。

上の抽出の規則はこれを拾えなかった。スラッシュも拡張子も無いので、56件の中に**最初から入っていない**。

対照を置くと理屈がはっきりする。`WRITING_STYLE.md` も `~/CLAUDE.md:64` で裸の名前で書かれている。ただしプロジェクトの層が `~/projects/dung-azure-flame/WRITING_STYLE.md` とパスを書いているので、そちらは復元でき、**欠陥ではない**。

**裸の名前が危険で、どんな抽出の規則もその全部は拾えない。** バッククォートを1つずつ人が読む工程だけが、この種類を閉じる。**その工程が、あなたが買っているものだ。**

### 3b. 層をまたぐ重複

24組のルールが複数の層に現れる。24組すべてを厳密な文字列で照合し、次に箇条書きの記号・空白・末尾の句読点を正規化してもう一度照合した。**バイト単位で一致が2組、正規化後に一致がもう1組、残る21組は部分的にしか重ならない。**

| 一致の度合い | 層A | 層B |
|---|---|---|
| バイト一致 | global:8 | project:60 |
| バイト一致 | global:11 | project:64 |
| 正規化後に一致 | global:16「技術固有名詞、ファイル名、コマンド名、製品名、API 名だけは英語のままでよい」 | project:143（同じ文を箇条書きに。末尾の句点が無く「API名」に空白が無い） |
| **部分のみ** | global:17「それ以外は日本語で説明し、短くするために意味を圧縮しない」 | project:145（後半の節だけを箇条書きに） |

最後の行が面白いところで、**「何組が重複しているか」で止めてはいけない理由**でもある。プロジェクトの層はグローバルのルールの*半分*しか持っていない。単独で読むと、元より狭い意味になる——「日本語で説明する」の半分が、単に消えている。

これが、矛盾になる手前の**層のずれ**の姿だ。類似度の点数だけでは、21組の部分的な重なりのうちどれが無害な言い換えで、どれが黙って狭めているのかは分からない。**その切り分けは読むことでしかできない。**

重複は費用の問題ではない（第1節）。**所有権**の問題だ。同じルールが2つの層にあると、片方を直してももう片方が生き続け、しかもどちらのファイルも「もう一方がある」と書いていない。

## 5. 直すべき上位3件（そのまま貼れる差分つき）

### 直し1 — 従えないルールを、従える形にする（効果が最大）

このルールたちは今日この時点で守れない。この報告書の他の項目は劣化の話だが、これは**はっきりした失敗**だ。

```diff
  # home CLAUDE.md (~/CLAUDE.md:134)
- ・ポートとプロファイルの割り当てはメモリ `cdp-ports.md` を参照する
+ ・ポートとプロファイルの割り当ては
+   `~/.claude/projects/-home-namakusa/memory/cdp-ports.md` を参照する
+   （★このプロジェクトのmemoryスコープには無いので、名前だけでは辿れない）
```

```diff
  # home CLAUDE.md (~/CLAUDE.md:69)
- ・ゲームは `GAME_QUALITY_FRAMEWORK` に従う
+ ・ゲームは `~/projects/spell-cascade/GAME_QUALITY_FRAMEWORK.md` に従う
```

一般化すると：**ルールが依存する参照は、そのルールが動く領域から解決できる形で書く。** 裸のファイル名が安全なのは、そのファイルが今の領域に在るときだけで、**見ただけでは分からない**。

### 直し2 — 重複したルールに、持ち主の層を1つ決める

```diff
  # project CLAUDE.md
- - 技術固有名詞、ファイル名、コマンド名、製品名、API名だけは英語のままでよい
- - 短くするために意味を圧縮しない
+ （文体の規則はグローバル指示書が正本。ここでは繰り返さない）
```

ルールが本当に全体のものなら、**より具体的な層のほうの写しを消す**。上書きするときだけ手元に写しを残し、そのときは「これはグローバルの規則を置き換える」と書く。次に編集する者が、2つ目の写しの存在を知れるように。

これは24組すべてに当てはまる。バイト一致の2組は個別の判断が要らないが、残る22組は要る。global:17 / project:145 の組がその理由を示している——手元の写しは、すでに狭い意味へずれていた。

### 直し3 — 曖昧な指示に、足がかりを1つずつ付ける

意図を書き換えてはいけない。**観測できるようにする条件を足す**だけだ。

```diff
  # global CLAUDE.md (~/.claude/CLAUDE.md:40)
- - 複雑な問題には、計算リソースを惜しまず投入しろ
+ - 3ファイル以上にまたがる調査、または同じ失敗を2回踏んだ時は、
+   自分で続けずサブエージェントか別の観測手段へ切り替えろ
```

```diff
  # home CLAUDE.md (~/CLAUDE.md:87)
- ・相談はしてよいが、返答待ちで停止しない。最終判断は自分で行う
+ ・相談はしてよい。ただし相談を投げた同じ応答の中で、
+   返答に依存しない作業を1つ着手すること。最終判断は自分で行う
```

書き換えた側は長くなる。それが取引だ。**検査できるルールはトークンを食うが、圧力の下でも生き残る。願望のルールは安いが、蒸発する。** 第1節がトークンの側はほぼ無料だと示しているので、この取引は一方的に得だ。

## この報告書がどう作られたか

最初の自動の走査は**壊れた参照17件**と報告した。2回目は**5件**。1件ずつファイルシステムに当てて確かめたら、生き残ったのは**1件**——そして**2件目の本物**は、走査が見ていた範囲の外に座っていた（第3a節）。

- 1回目は、スラッシュコマンドもシェルのコマンド行も日付の雛形もパスとして数えていた
- 2回目は基準パスに欠陥があった。`memory/foo.md` と書かれた参照を `memory/memory/foo.md` で探しており、**実在する3つのファイル**を「無い」と報告する寸前だった
- ディレクトリを直接一覧して決着がついた

この回、確かめない走査は**本物1件に対して偽物16件を出荷し、しかも1件を見落としていた**。上に書いた発見はすべて、書き留める前に手で確認してある。**走査は安いほうの半分だ。**
